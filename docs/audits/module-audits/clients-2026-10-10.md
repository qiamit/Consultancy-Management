## AUD-01 — Permanent delete still stops on the client’s own site or contact

- **Priority:** P1
- **Status:** Open
- **Where:** `delete_master_rows` for `clients`, called as the signed-in user. Client Directory archive is a separate path and did archive.
- **Evidence:** A `ZZ TEST` client with a `Registered Office` site was left in place. The RPC payload named `client_sites`. A client with one `client_contacts` row was also blocked (`ref_count` 1) while a second `ZZ TEST` client with no children was deleted. Deleting the child rows first, then deleting the client, removed the row. `backend/database/migrations/20261010120000_client_name_delete_and_storage.sql` is written and not applied.
- **Fix plan:** Apply that migration. `master_reference_counts` must skip the client’s own `ON DELETE CASCADE` children. `delete_master_rows` must still refuse a client linked from a quotation or another restricted table.
- **Acceptance:** After migrate, an admin permanently deletes a `ZZ TEST` client that has only its own sites, contacts, and certificates. A client linked from a quotation is still skipped.

## AUD-02 — Certificate file delete is rejected

- **Priority:** P1
- **Status:** Open
- **Where:** Bucket `client-certificates`, `deleteClientCertificate` in `clientsApi.ts`. The certificate row insert was also checked.
- **Evidence:** Upload of a 1×1 PNG succeeded. Inserting `document_number` failed with “Could not find the 'document_number' column”. Inserting the base columns (`cert_name`, `file_name`, `storage_path`) succeeded. `storage.remove` returned 403, message “new row violates row-level security policy”. The database row could then be deleted. The storage object stayed. This is the same `storage.protect_delete` block described in the 2026-10-09 audit. The fix is in `20261010120000_client_name_delete_and_storage.sql` and is not applied.
- **Fix plan:** Apply that migration so the storage API can delete when the session is the storage admin. Keep the page’s retry that omits `document_number` until that column exists.
- **Acceptance:** After migrate, upload a small PNG on a `ZZ TEST` client, open it, and delete it. No certificate row and no storage object remain.

## AUD-04 — A form opened on a wide window becomes a sliver when the window is narrowed

- **Priority:** P2
- **Status:** Open
- **Where:** Add New Client dialog. The same sheet class is on Add New IS Code.
- **Evidence:** The dialog was opened at 1280px (left 268, width 1012). After the viewport was set to 360px without closing it, the dialog stayed at left 268 and width 92. At 390px in that same open state it was left 268 and width 122. Opening Add New Client when the viewport was already 360px used left 0 and width 360, with no horizontal overflow, and Save & Close was 40px tall. At 390px opened from that narrow state the dialog was width 390. At 768px the docked sidebar left a 500px dialog with no overflow. Cards (`lg:hidden`) showed at 360px and the table (`hidden lg:block`) was `display: none`. The page `scrollWidth` stayed equal to the viewport.
- **Fix plan:** When the sidebar closes or the viewport crosses the `lg` breakpoint, recompute `--app-dialog-overlay-left` while a dialog is already open.
- **Acceptance:** Open Add New Client at 1280px, narrow the window to 360px and 390px, and the sheet still fills the width beside a closed sidebar. Buttons stay usable. The page does not scroll sideways.
