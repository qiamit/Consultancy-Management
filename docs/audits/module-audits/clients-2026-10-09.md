## AUD-01 — Copy keeps the GST and a second client is saved

- **Priority:** P1
- **Status:** Done
- **Where:** Client Directory copy and Add New Client (Quotation, BIS Licenses).
- **Evidence:** Amit, 2026-10-10: the same GSTIN may belong to another unit in the same state. A firm name must be unique in the country. `clients_company_name_lower_uidx` already rejects a second trimmed name. There is no GST unique index, and one must not be added.
- **Fix plan:** Exact name is a hard block, including Save Anyway. A similar-but-not-equal name still warns. A hit whose similarity is 1 only because the GSTIN matches is ignored until the new `find_similar_clients` is migrated.
- **Acceptance:** Two clients may share a GSTIN when the firm names differ. Saving a second client with the same firm name shows “A firm with this name already exists.” and does not insert a row.
- **Log:** 2026-10-10. `clientsApi.ts` `firmNameTaken`, `ClientsMasterPage.tsx` save, `AddClientDialog.tsx` save, migration `20261010120000_client_name_delete_and_storage.sql`. The name check works before migrate. The RPC change applies on migrate.

## AUD-02 — Permanent delete is blocked by the client’s own child rows

- **Priority:** P1
- **Status:** Blocked
- **Where:** Client Directory, Delete Permanently. `master_reference_counts` and `delete_master_rows`.
- **Evidence:** The app returned “Deleted 0.” The three dummy rows were blocked by `client_sites`, `client_contacts`, and `client_certificate_files` even though those foreign keys are `ON DELETE CASCADE`.
- **Fix plan:** New `master_reference_counts` skips `confdeltype = 'c'` for `clients`. `delete_master_rows` returns certificate `storage_paths` collected before the delete. The Client Directory removes those paths the same way IS Codes does. Quotations and other `ON DELETE RESTRICT` / `SET NULL` links still block.
- **Acceptance:** After migrate, an admin can permanently delete a client that has only its own sites, contacts, and certificates. A client linked from a quotation or another restricted table is still skipped.
- **Log:** 2026-10-10. Migration written, not applied. Reason: needs `npm run db:migrate`. The three dummy clients are removed separately so they do not stay in the directory.

## AUD-04 — Certificate storage rejected a call while a file row remained

- **Priority:** P2
- **Status:** Blocked
- **Where:** `deleteClientCertificate` in `clientsApi.ts`, bucket `client-certificates`.
- **Evidence:** Upload of the test PNG succeeded. Delete returned `StorageApiError` 403, message “new row violates row-level security policy”. The storage policies already allow a user who can edit Client Master. The 403 text is the storage API rewriting `42501` from `storage.protect_delete()`, which blocks every delete unless `storage.allow_delete_query` is true. This image’s Storage API does not set that flag.
- **Fix plan:** `storage.protect_delete()` allows the delete when that flag is true or `session_user` is `supabase_storage_admin` or `supabase_admin`. Direct SQL from other roles still raises `42501`. The certificate row goes away with the dummy client. The storage object stays until this function is migrated.
- **Acceptance:** After migrate, upload a small PNG on a saved client, see it, open it, and delete it. No certificate row and no storage object remain after delete.
- **Log:** 2026-10-10. Migration written, not applied. Reason: needs `npm run db:migrate`.
