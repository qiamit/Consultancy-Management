# CMPF-311 Own SIT Module Audit — 2026-10-12

## Scope and result

Audited the CMPF-311 Own SIT module after the production notification reported no SIT rows and no Notes. The final logged-in production run on Asian PVC & Plastics, IS 17425:2020, using `PM IS 17425.pdf`, completed `All Documents generated` and populated Annexure C (5 rows), SIT Test Table (36 rows), and Notes (1 row). The generated content was inspected in the UI and not saved to the production project.

Follow-up: repeated production runs first revealed non-JSON replies, then a network fetch error. Safe backend diagnostics identified active model `deepseek-v4-pro`, `finish_reason=length`, and a response containing `reasoning_content` but no final content. CMPF-311 requests now disable DeepSeek thinking, reserve 8,192 output tokens, accept text-part content arrays, and surface safe provider/finish diagnostics on genuinely empty replies. The PDF extractor preserves closer column gaps; a source-table parser is available when extracted text contains recognizable column-delimited rows. The final production run populated all three tables. No project data was saved and no raw PDF text, reasoning text, or API key was logged.

## Findings

### AUD-01 — Valid JSON can be silently normalized to zero rows

- **Priority:** P1
- **Status:** Pass
- **Checked:** `generateCmpf311Section()` in the CMPF-311 module; caller `Cmpf311ModuleFields.generate()`.
- **Evidence:** `frontend/web/src/features/bis/projects/cmpf311Model.ts` now searches common nested response envelopes, normalizes key names, supports alternate SIT fields and string/array rows, and retries content after a valid-but-empty response. The in-memory `ZZ TEST` harness passed canonical and nested/aliased response fixtures for the three targets.
- **Action that passed:** Nested `result.data.SIT_Test_Table` data with alternate `clauseNo`, `testRequirement`, `R_or_S`, and sample/frequency keys maps into the expected SIT row instead of becoming empty.

### AUD-02 — PDF text extraction can lose SIT table structure

- **Priority:** P1
- **Status:** Open
- **Checked:** Master PDF loading, multi-PDF selection, extraction, and AI request construction in the CMPF-311 module.
- **Evidence:** `frontend/web/src/features/bis/projects/cmpf311Model.ts:183-234` extracts only PDF text-layer items, groups them by approximate y coordinate, sorts by x, and flattens each line. No OCR or page-image/table input is sent to the model. `frontend/web/src/features/bis/projects/Cmpf311ModuleFields.tsx:168-172` sends the flattened text (up to 120,000 characters) to generation. A scanned table or a table whose cells do not share text baselines can therefore reach the model without usable row/cell associations. The exact Product Manual that failed was not available in this checkout, so this remains a likely failure path, not a confirmed diagnosis for that particular PDF.
- **Evidence:** `cmpf311Model.ts` now emits column separators for smaller PDF text gaps and can parse column-delimited table rows when the model returns no usable SIT data. The final production extraction produced 36 meaningful SIT rows, spanning clauses 4.1 through 8. This verifies usable extraction for the current manual, but the rows were not compared one-by-one against a rendered source table and OCR remains unavailable for image-only PDFs.
- **Fix plan:** Compare the 36 live rows against the source table, then add representative multi-page and scanned-PDF fixtures; add OCR or a document-capable path for image tables if needed.
- **Acceptance criteria:** Source comparison confirms row and column fidelity across continuation pages, and image-only tables are identified or processed before AI extraction.

### AUD-03 — DeepSeek thinking exhausted the CMPF-311 output budget

- **Priority:** P1
- **Status:** Pass
- **Checked:** CMPF-311 prompts and retries through the production QI Assistant function; logged-in Chrome, production module.
- **Evidence:** The safe diagnostic identified `deepseek-v4-pro`, `finish_reason=length`, and message fields `role, content, reasoning_content`. Backend code now disables DeepSeek thinking for CMPF-311, reserves 8,192 output tokens, and parses text-part arrays. The post-deploy live run returned success and populated 5 Annexure C rows, 36 SIT rows, and 1 Notes row.
- **Action that passed:** Generate All on the same production manual populated all three tables; the UI showed `All Documents generated`. Generated values were not saved.

### AUD-04 — Empty provider replies need safe diagnostics

- **Priority:** P2
- **Status:** Pass
