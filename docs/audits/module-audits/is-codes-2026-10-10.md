## AUD-01 — Delete document stops before the file row is removed

- **Priority:** P1
- **Status:** Open
- **Where:** `deletePopupFile` in `IsCodesMasterPage.tsx`, bucket `is-code-files`.
- **Evidence:** Upload of a 1×1 PNG succeeded and the `is_code_files` row inserted. `storage.remove` returned 403, message “new row violates row-level security policy”. `deletePopupFile` throws on that error before the `is_code_files` delete (`IsCodesMasterPage.tsx` around the storage `remove` call). The same 403 is what `20261010120000_client_name_delete_and_storage.sql` changes in `storage.protect_delete`. That migration is not applied. The test’s database file row was deleted afterwards by a direct table delete; the storage object stayed.
- **Fix plan:** Apply the storage `protect_delete` change. A failed storage delete must not be required to block removing the `is_code_files` row once the object is already unreachable, but after the migration the storage delete itself should succeed.
- **Acceptance:** After migrate, upload a small PNG on a `ZZ TEST` IS code, then Delete document. The row and the storage object are both gone, and the footer does not show the 403 text.
